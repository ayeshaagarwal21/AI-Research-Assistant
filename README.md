# 📚 AI Research Assistant (RAG)

Upload PDF documents and ask questions about them. Answers are generated by
Google Gemini **only from your documents**, and every answer shows the file and
page it came from.

## Features

- **Accounts** - sign up / log in (JWT auth, scrypt-hashed passwords, SQLite)
- **Private workspaces** - each user has their own documents and chat history
- **Multi-PDF upload** - add files over time; re-uploading a file replaces it; remove files individually
- **Retrieval-Augmented Generation** - chunking -> Sentence-Transformer embeddings -> FAISS cosine search -> Gemini
- **Source citations** - file name, page number, relevance score and a text snippet for each answer
- **ChatGPT-style conversation history** - every research thread is saved as its own chat, auto-titled from the first question, searchable in the sidebar, and resumable after sign-in
- **Three answer modes** - *Ask about my documents* (grounded, with sources), *Solve questions in my PDFs* (finds the questions written inside a PDF and answers them) and *General knowledge* (no PDFs needed)
- **Solve PDF questions** - say "answer all the questions", "solve Q3" or "answer the questions on pages 2-4 of exam.pdf"; the app notices this automatically in the default mode
- **Voice input** - tap the mic button inside the chat box, speak, and the question is transcribed and sent (needs Streamlit 1.52+; older versions get a sidebar recorder)
- **Voice output** - a Listen button reads any answer aloud (citations and markdown are stripped first)
- **Image questions** - upload a screenshot or photo of a question; Gemini reads it and answers (typed or spoken follow-ups work too)
- **Image generation** - describe an image in the sidebar and Gemini generates it (rate-limited per user)
- **User profile analytics** - stores account creation time, last login and sign-in count; passwords are scrypt-hashed and never stored in plaintext
- **Safe failures** - clear messages for scanned/encrypted/corrupt PDFs, oversized files, missing API key, expired sessions

## Architecture

```
Streamlit UI (app.py)
      |  HTTP + JWT
      v
FastAPI backend (backend/main.py)
  |-- /auth    signup, login, me           -> SQLite (users)
  |-- /upload  PDFs -> text -> chunks -> embeddings -> per-user store
  |-- /chat    question -> embed -> FAISS top-k -> Gemini -> answer + sources
  |-- /conversations chat threads + messages -> SQLite
  |-- /history legacy history/clear-all     -> SQLite
  |-- /voice   speak (text -> MP3), transcribe (audio -> text)
  |-- /images  generate (prompt -> image)
  |-- /vision  ask (screenshot/photo + optional note -> answer)
  |-- /documents list / delete uploaded files
```

```
backend/app/
  api/        route handlers (auth, upload, chat, history)
  core/       config (env vars), security (hashing + JWT), auth dependency
  db/         SQLite helpers
  prompts/    RAG prompt template
  schemas/    Pydantic request/response models
  services/   LLM client + RAG answer generation
utils/        pdf_reader, chunking, embeddings, vector_store, retriever
tests/        unit tests
```

## Setup

```powershell
python -m venv venv
venv\Scripts\Activate.ps1          # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt

copy .env.example .env             # macOS/Linux: cp .env.example .env
# then edit .env: add your GOOGLE_API_KEY and a random SECRET_KEY
```

## Run

Open **two terminals** (both with the virtual environment activated):

```powershell
# Terminal 1 - backend
uvicorn backend.main:app --reload

# Terminal 2 - frontend
streamlit run app.py
```

Then open the Streamlit link (usually http://localhost:8501), create an account,
upload a PDF, click **Process documents**, and start asking questions.
Interactive API docs are at http://127.0.0.1:8000/docs.

> The first upload/question is slow because the embedding model
> (`all-MiniLM-L6-v2`, ~90 MB) is downloaded and loaded once.

## API overview

| Method | Path | Description |
|--------|------|-------------|
| POST | `/auth/signup` | Create account, returns a token |
| POST | `/auth/login` | Log in, returns a token |
| GET | `/auth/me` | Current user |
| POST | `/upload` | Upload one or more PDFs (multipart field `files`) |
| GET | `/documents` | List your documents |
| DELETE | `/documents?filename=x.pdf` | Remove one document (omit `filename` to remove all) |
| POST | `/chat/` | Ask a question with an optional `conversation_id` -> `{answer, sources[], conversation_id}` |
| GET | `/conversations` | List the signed-in user’s saved chats |
| POST | `/conversations` | Create a new empty chat |
| GET | `/conversations/{id}/messages` | Load one previous chat |
| PATCH | `/conversations/{id}` | Rename a chat |
| DELETE | `/conversations/{id}` | Delete one chat and its messages |
| POST | `/voice/speak` | Text -> MP3 audio |
| POST | `/voice/transcribe` | WAV audio -> `{text}` |
| POST | `/vision/ask` | Image (multipart field `image`) + optional `instruction` -> `{answer}` |
| POST | `/images/generate` | Prompt -> image (needs a Google key with image access) |
| GET | `/history` | Legacy aggregate history endpoint |
| DELETE | `/history` | Clear all chats and messages for the current user |

All endpoints except signup/login need the header `Authorization: Bearer <token>`.

## Tests

```powershell
pytest -q
```

The upgraded project includes conversation persistence and database migration logic. Existing v5 databases are migrated automatically when the backend starts; old messages are placed into a `Previous research` conversation.

Covers password hashing, tokens, the database layer, the per-user vector store,
retrieval edge cases, PDF reading and speech text cleaning.

## Design notes

- **Per-user stores:** vectors are saved as `embeddings.npy` + `chunks.json` under
  `vector_store/user_<id>/`. The FAISS index is rebuilt from them and cached in memory,
  which makes deleting one document simple and reliable.
- **Cosine similarity:** embeddings are normalised and searched with an inner-product
  index, so scores are easy to interpret (higher = more relevant).
- **Grounded answers:** the prompt tells the model to reply "I couldn't find that
  information in the uploaded documents." when the context doesn't contain the answer.

## Notes on the voice and image features

- Solving PDF questions reads the actual pages (up to about 300,000 characters per request), so long documents are cut off with a note; ask for a page range to cover the rest. Questions that depend on diagrams or images inside the PDF can't be read.
- The mic only works on `localhost` or HTTPS, and the browser asks for permission once.
- Speech recognition and text-to-speech use free Google web services, so they need internet.
- Image generation often needs a billing-enabled Google key; if it fails with a 502, check
  your key's access and the `IMAGE_MODEL` name in Google's current docs.
- Image questions are limited to PNG/JPG/WEBP/GIF up to 8 MB. The uploaded image is not stored; only a text note and the answer are saved to history.
- Generated images are shown for the current session only (not saved to history).

## Known limitations / future work

- Scanned (image-only) PDFs need OCR - not included.
- Image generation is not saved in history; voice language is English by default (`hi-IN` / `hi` are easy to switch).
- Only PDF input is supported (the `/upload` endpoint is easy to extend to .docx/.txt).
- The in-memory index cache assumes a single server process; use one `uvicorn` worker.
- The `/chat` endpoint returns the full answer at once (no token streaming yet).


## Separate admin portal

The normal `app.py` UI is unchanged. A completely separate admin portal is provided in `admin_app.py`.

1. Add these values to `.env`:
   ```env
   ADMIN_EMAIL=your-admin-email@example.com
   ADMIN_PASSWORD=your-strong-admin-password
   ADMIN_SECRET_KEY=your-separate-long-random-admin-key
   ```
2. Start the backend:
   ```powershell
   uvicorn backend.main:app --reload
   ```
3. Start the normal user app as before:
   ```powershell
   streamlit run app.py
   ```
4. In a separate terminal, start the private admin portal:
   ```powershell
   streamlit run admin_app.py --server.port 8502
   ```
5. Open `http://localhost:8502` for the admin portal.

Admin credentials are separate from normal user credentials. The admin dashboard exposes only non-secret user metadata and aggregate application statistics; password hashes are never returned.
